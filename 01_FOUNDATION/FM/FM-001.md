# FM-001 — Foundry Meta-Model

**Version:** Genesis G-0.1  
**Status:** Frozen  
**Authority:** CONST-001  
**Behavioral Authority:** IP-001  
**Depends On:** CONST-001, IP-001

## Purpose

FM-001 defines the universal structure from which every persistent institutional object SHALL be derived.

## Universal object model

OBJECT =
IDENTITY + TYPE + MEANING + STATE + AUTHORITY + RELATIONSHIPS + EVIDENCE + VALIDATION + HISTORY

Each ObjectType SHALL specify whether each domain is Required, Optional, or Prohibited.

## Identity

Every persistent object SHALL possess exactly one immutable ObjectID.

ObjectID identifies the institutional object, not its filename, storage location, software representation, or title.

ObjectID SHALL NOT encode mutable meaning.

## Type

Every object SHALL possess exactly one primary ObjectType.

Foundation types:
- CONST
- IP
- FM

Core types:
- OBS
- INQ
- EVD
- DEC
- CAP
- STD
- SPEC

Provisional types:
- PRN
- LAW
- KNW
- FW
- PROC
- EXP
- LES
- REF

Provisional types require separate specifications before becoming mandatory.

## Meaning

Minimum semantic fields:
- Purpose
- Scope
- OutOfScope

Purpose SHALL state institutional function, not merely contents.

## State

Every object SHALL possess one authoritative current lifecycle state.

Each ObjectType Specification SHALL define:
- states;
- transitions;
- triggers;
- transition authority;
- preconditions;
- failure transitions.

A transition is valid only when trigger, preconditions, authority, required evidence, and validation conditions are satisfied.

## Authority

Authority SHALL be role-based.

Minimum fields:
- Owner: RoleID
- Reviewer: RoleID[]
- RatifyingAuthority: RoleID
- AuthorityLevel

Authorship and authority are separate.

## Relationships

Relationships SHALL be typed.

Genesis relationship vocabulary:
- DEPENDS_ON
- DERIVED_FROM
- REFERENCES
- SUPPORTS
- CONTRADICTS
- VALIDATES
- INVALIDATES
- IMPLEMENTS
- PRODUCES
- CONSUMES
- GOVERNS
- GOVERNED_BY
- SUPERSEDES
- SUPERSEDED_BY
- REFINES
- SPLITS_FROM
- MERGED_INTO
- GENERATED_BY

## Evidence

Evidence policy is type-specific.

Possible evidence classes:
- OBSERVED
- MEASURED
- EXPERIMENTAL
- DOCUMENTARY
- EXTERNAL
- DERIVED
- SIMULATED

Evidence support does not automatically establish truth.

## Validation

Every ObjectType SHALL define its validation contract.

Minimum validation dimensions:
- Structural
- Semantic
- Evidentiary
- Behavioral
- Empirical
- Governance

An object SHALL NOT be authoritative if mandatory validation conditions are unsatisfied.

## History

History SHALL be append-only at the institutional level.

Every revision SHALL preserve:
- prior state;
- change;
- reason;
- authority;
- effective date.

ObjectID remains constant across revisions.

## Immutability

Identity-immutable:
- ObjectID
- ObjectType
- CreationDate
- CreatedBy

Historical-immutable:
- previous revisions

Mutable:
- current fields through authorized transitions

## Dependencies

Dependencies SHALL be explicit and typed.

Genesis dependency classes:
- NORMATIVE
- FUNCTIONAL
- EVIDENTIARY
- GOVERNANCE
- REFERENCE

Mandatory unresolved dependencies prevent activation unless an approved exception exists.

## Inheritance

Object types MAY inherit common structure. Inheritance SHALL NOT alter the universal identity model.

## Composition

Objects SHOULD reference authoritative objects rather than duplicate authoritative content.

## Merge

A merge SHALL preserve source identities, merge decision, resulting object, and lineage.

## Split

A split SHALL preserve lineage from the source object to every resulting object.

## Contradiction

Contradiction is an explicit relationship. A contradiction does not automatically invalidate either object.

Resolution requires authority, evidence, scope, applicability, and temporal context.

## Universal lifecycle contract

Minimum lifecycle:

DRAFT → REVIEW → ACTIVE → SUPERSEDED / ARCHIVED / INVALID

Object types MAY add intermediate states but SHALL NOT bypass higher-level authority.

## Machine validation contract

A future implementation SHALL be capable of evaluating:
- UniqueIdentity()
- ValidType()
- ValidState()
- ValidAuthority()
- ValidRelationships()
- ValidDependencies()
- ValidEvidence()
- ValidTransitions()
- ValidHistory()
- ValidPayload()
- ConstitutionallyCompliant()

## Implementation independence

A future implementation SHALL preserve object identity, history, relationships, authority, and meaning across migration between storage or software representations.

## Boundary

FM-001 SHALL NOT define substantive validity of an Observation, Inquiry, Evidence record, Decision, Capability, Standard, or Specification. Those belong to their respective type specifications.
